# casebrief-lite の小さなテスト例

これは検証用の依頼と観察項目であり、回答テンプレートではない。原則としてケースごとに新しい会話で試す。題材は git 管理下の一時リポジトリ（小さな関数とそのテストを 1 つずつ置き、最初のコミットを済ませたもの）で用意する。PR と Issue のケースだけは GitHub 上の既存の PR・Issue を読むが、書き込みは行わない。実行結果を評価する人は、見出しや表の形だけで判定せず、読んだファイルと出力の中身を突き合わせる。

依頼例は Codex の `$casebrief-lite` 表記で書いている。Claude Code では `/casebrief-lite` に読み替える。Claude Code の非対話モード（`claude -p '/casebrief-lite ...' --output-format stream-json --verbose`）ではツール呼び出しの記録が取れる。Codex では `codex exec --json '$casebrief-lite ...'` で試せる。スキルは、一時リポジトリの `.claude/skills/casebrief-lite` と `.agents/skills/casebrief-lite` に原本への symlink を置けばそのプロジェクトだけで有効になる。

## 1. 未コミットの差分

準備: 一時リポジトリで、関数の境界条件を 1 か所変える（例: `if age > 18` を `if age >= 18` にする）。コミットはしない。

依頼: `$casebrief-lite`

観察: `git diff HEAD` と未追跡ファイルを読んでいるか。4 見出しがそろい、テスト観点の各行で 6 列が埋まっているか。修正の確認・回帰・Never が各 1 行以上あるか。境界の 17・18・19 のように、範囲内の端と範囲外の隣が別の具体例になっているか。既存テストの場所を挙げているか。

## 2. 引数の受け取り（Codex）

準備: ケース 1 の変更をコミットし、さらに別の変更をもう 1 コミット積む。

依頼: `$casebrief-lite HEAD~2...HEAD`

観察: `$ARGUMENTS` が置き換わらない環境でも、`$casebrief-lite` に続く `HEAD~2...HEAD` を引数として扱い、コミット範囲の diff を読んでいるか。未コミットの差分を読みに行っていないか。

## 3. まだコードが無い修正

依頼: `$casebrief-lite ユーザー一覧の並び順を、登録日時の昇順から更新日時の降順に変えたい`

観察: 説明に出てくる語で grep し、変更が入りそうな場所を挙げているか。同じ更新日時の並び、更新日時が空のデータなど、仕様に無い期待を仮定として書き、依存する観点の番号を付けているか。コードを書き換えていないか。

## 4. PR と Issue

依頼: `$casebrief-lite #<既存の PR 番号>`、続けて別の会話で `$casebrief-lite issue <既存の Issue 番号>`

観察: PR では `gh pr view` と `gh pr diff` を使い、手元に head が無ければ `git fetch origin pull/<番号>/head` で読んで作業ツリーを切り替えていないか。Issue ではコードが無い修正として扱っているか。PR・Issue へのコメントや状態変更をしていないか。

## 5. 対象が無い時

準備: 差分の無いクリーンな一時リポジトリ。新しい会話で、前の話題が無い状態にする。

依頼: `$casebrief-lite`

観察: 対象を 1 行で尋ねて止まり、存在しない修正を作り出していないか。

## 6. casebrief への提案と書き出し

依頼: `$casebrief-lite 会員登録画面を新しく作り、メール認証と利用規約の同意を入れたい`

観察: 新しい画面に当たるので、末尾で casebrief に回すことを提案するか。提案に応じない限りファイルを書き出していないか。応じた場合は feature 名を尋ね、`test-design/<feature>/_intake/source.md` に実装の場所を書かず、仮定を `## 未確定` 節にまとめているか。

## 7. 自動適用しない設定

- `agents/openai.yaml` をYAMLとして解析し、`policy.allow_implicit_invocation` が文字列ではなく真偽値の `false` であることを確認する。
- `SKILL.md` の frontmatter に `disable-model-invocation: true` があることを確認する。Claude Code はこれで自動適用を抑止する。Codex はこのフィールドを解釈せず、抑止は `openai.yaml` に依存する。
- 実環境の新しい会話で、呼び出しなしに `この変更のテスト観点を出して` と依頼する。利用可能なら、スキルの選択や注入の記録で `casebrief-lite` が自動適用されていないか確認する。出力の形が似ているだけでは判定しない。記録が取れなければ設定確認と実際の注入確認を区別し、後者は未確認とする。

## 検証結果の記録方法

形式チェック（YAML、名前、リンク、設定）、自己レビュー（要件との整合）、実行テスト（実際の出力と読んだファイル）を分けて記録する。実行テストは使った環境、依頼、出力、観察結果、未確認点を残す。未実行を合格と報告せず、少数の試行を一般的な品質保証にしない。
